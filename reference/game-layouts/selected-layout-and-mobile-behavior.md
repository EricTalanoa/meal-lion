# Meal-lion layout decisions

Desktop: user selected layout B (b-split-kitchen.png). Preserve this choice in future implementation.

Mobile proposal: mobile-keyboard-states.png shows browsing and focused guess entry. This mobile design is proposed, not yet user-approved. Generated using the built-in image-generation tool, referenced to desktop B.

Behavior specification:
- Browsing: compact header/modes, kitchen animation, ingredient clues, guess history, guess composer.
- Typing: native OS keyboard, kitchen collapses to a short strip, revealed ingredients remain visible, suggestions replace history. Composer stays above the keyboard within the visible viewport, not below it. On short screens hide modes and secondary navigation first; permit suggestions/clues to scroll.
- Use native text input, not a drawn keyboard in production. Keyboard shown is illustrative; iOS and Android dimensions vary.
- Tap suggestion to select; tap Guess to submit. Selection mark is not correctness feedback. Prefer a radio dot or Selected label in actual implementation (generated mockup retained a checkmark).
- Suggestions come from the entire allowed dish catalog filtered by typed text, never the hidden answer or revealed clues. Example alternate dish is illustrative, not an approved addition to the 45-meal roster.
- Dismissing keyboard retains text/selection. Submitting a valid selected dish closes keyboard, restores kitchen and runs reaction; invalid/unselected text leaves keyboard open with guidance. Avoid automatic focus on initial page load.
- Long ingredient sets must wrap/scroll with text labels available; do not shrink seven to ten clues into unreadable phone tiles as in the illustrative closed-keyboard image.
- Target at least 44px controls and 16px input text, account for safe areas and browser chrome. Support reduced motion and keyboard resizing without jumpy layout.
- Before shipping, test keyboard open/close, landscape rotation, long suggestions, scrolling, and submit on real iOS Safari and Android Chrome. No real-device keyboard behavior has been tested by this image mockup.
